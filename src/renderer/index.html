Spacing

Behaviour

There is no setting for not hiding them. A workspace has to put the windows you are not looking at somewhere, and these are the three ways Windows offers. To leave one application alone, add it under Keep on screen everywhere further down: komorebi never touches those, so they are never hidden by any of these.

The resize step is the only pixel amount komorebi has. It is used by resize-edge and resize-axis. Moving a window swaps it with its neighbour instead of shifting it by pixels, so there is nothing to set there. This one applies live.

Screen edges

Space reserved around the whole screen, for example to keep the bar clear.

Screens

Each screen keeps its own workspaces. komorebi matches these blocks to physical screens by index, so the order here is the order Windows reports them in.

Workspaces

Per workspace you can override the global floating behaviour and the gaps. Inherit leaves the global setting in charge.

Shape of a layout

Where a layout puts its splits, per workspace. komorebi's own custom layouts are marked end of life in the schema, so this sets layout_options, which is the supported way to do the same thing.

Layout rules

Switch layout automatically as windows open on a workspace.

Keep on screen everywhere

komorebi never touches these, so they are never hidden when you switch workspace and stay on top of whatever is there. It is the closest thing to pinning.

Send apps to a workspace

Matched on launch, so an app always lands where you expect it.

Borders

komorebi has no numeric corner radius. Rounded is the Windows 11 corner, Square the Windows 10 one. Offset is the shape control: negative tucks the border under the window, positive pushes it out into the gap.
